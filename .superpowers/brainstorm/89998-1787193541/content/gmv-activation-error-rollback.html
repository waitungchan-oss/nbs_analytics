第三段｜生效、失敗與回滾狀態機

正式淨 GMV 採 fail closed：任何 stale、checksum 或 transaction 問題都保留上一個 active version。

確認與生效流程
阻塞與警告規則
必須阻塞
  • 缺少必要欄位或沒有可用退款列
  • file hash／preflight fingerprint 不一致
  • 正式營收 generation 已改變
  • 同一批次已確認，禁止重複生效
  • snapshot checksum 或 transaction 寫入失敗
可確認但必須顯示警告
  • SQLite 找不到或被收入規則排除
  • 重複退款列、超額退款、未知狀態
  • 未知狀態只進「總退款」，不進正式淨 GMV
  • 使用者確認時保存 warning acknowledgement
Rollback 規則
gmv_scope_events（append-only）

每次 ACTIVATE／ROLLBACK 都新增事件，保存 from/to version、原因、操作者、時間及 checksum。Rollback 只切換 active pointer，不刪批次、明細、對帳結果或 snapshot。

因此可以回答：哪份退款檔、哪套收入 generation、哪個規則版本，在何時令正式淨 GMV 發生變化。
