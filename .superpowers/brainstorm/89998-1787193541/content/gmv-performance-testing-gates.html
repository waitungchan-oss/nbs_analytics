第四段｜效能與驗收 Gate

「不影響現有網頁讀取時間」以結構隔離 + benchmark 雙重保證，不以主觀感受判斷。

Hot-path 隔離
現有首頁／經營分析大盤

零新增 GMV 工作

  • 不查詢任何 gmv_ table/view
  • 不驗證 migration、不重算退款
  • 既有 revenue cache token 不變
  • Forecast／WAPE／Backtest 路徑不變
正式淨 GMV 看板／匯出

使用者進入後才載入

  • Dashboard 只查 v_gmv_current_metrics
  • 索引鍵：active version + period + dimension
  • 完整 Excel 只在按下載時生成
  • workbook cache key：version + export schema
可測量效能標準

首頁結構 Gate

以 query spy／contract test 證明現有首頁載入不呼叫 GMV repository，也不使現有 cache 失效。

首頁 Benchmark

同機器、同資料，變更前後各 10 次 warm run；median regression 不超過 300 ms，且不超過基準的 5%。

GMV Read Model

active metric snapshot indexed query 目標 < 100 ms；GMV 看板資料準備目標 < 1.5 s。

DB 體積 Gate

版本只存稀疏 adjustment，不複製未受影響營收列；測試檢查 snapshot row count 與退款影響範圍一致。

Migration 與索引
部署／maintenance path，禁止放入 Streamlit page render

Migration 前建立 SQLite backup，使用 schema version 與 idempotent validation；部署時一次執行。必要索引涵蓋 batch_id、source_receipt_no、version_id、(version_id, period, dimension) 與唯一 active pointer。

驗收矩陣
從計算正確到實際 UI
  1. Unit：總退款／已退款、期間 C、cap、比例分配、匹配分類。
  2. Repository：migration、duplicate file、stale generation、atomic commit、rollback、event log。
  3. Parity：同一退款檔的正式淨 GMV與現有 session-only 已退款結果一致。
  4. Dashboard：雙正式口徑並列、總退款保留、active version／資料期間／來源批次清楚顯示。
  5. Export：完整報表同時含總退款與已退款，正式 sheet 使用已退款；稽核 sheet 可追到 batch/version。
  6. Performance：首頁 query contract + 10-run benchmark + GMV indexed read。
  7. Release：完整 pytest、findings-first review、Hermes、實際 Streamlit UI 驗收。
