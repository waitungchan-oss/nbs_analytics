第二段｜SQLite 資料模型

設計原則：confirmed batch 不可修改；active version 可切換；snapshot 只保存扣減 delta 與頁面需要的預聚合數字。

A. Intake Ledger｜保存來源證據
gmv_refund_batches

用途：一次上傳／確認的退款批次。

batch_id · file_hash · source filename · row count · preflight status · confirmed at/by · source checksum

同一 file hash 防止重複確認；confirmed 後不可覆寫。

gmv_refund_items

用途：標準化後的每筆退款來源列。

item_id · batch_id · 收款單號 · 退款單號 · 退款狀態 · 退款金額 · 退款日期 · source row hash

同時保留原退款日期與原訂單期間關聯。

B. Reconciliation Ledger｜保存計算解釋
gmv_reconciliation_results

一筆來源單據 × 一個退款維度保存：總退款／已退款、匹配狀態、退款明細金額、原收款金額、實際扣減、超額退款、收入規則排除原因、rule version。

正式淨 GMV

  • 只讀「已退款」
  • 只計 FORMAL_MATCHED
  • 扣減不超過原收款

營運監控

  • 「總退款」仍完整保存
  • 規則排除與找不到不誤扣
  • 異常中心可追溯
C. Version + Snapshot｜正式生效與快速讀取

gmv_scope_versions

version_id、batch、revenue generation token、rule version、draft/active/retired、previous version、activated at/by、calculation checksum。

規則：同一時間只有一個 active version；切回前版不刪資料。

gmv_adjustment_snapshot

只保存被退款影響的收款列：原收款月份、退款月份、來源單據、退款前金額、扣減金額、退款後金額、分配比例。

稀疏 delta：不複製沒有退款的正式營收列。

gmv_metric_snapshot

預先保存 Dashboard 需要的月度／分社／銷售代表／業務類型聚合，以及「總退款」和「已退款」並列 KPI。

頁面熱路徑：直接查小型聚合表。

D. Stable Read Contract｜Consumer 不感知版本細節
v_gmv_current_metrics

只返回 active version 的 Dashboard KPI／排名／月度趨勢。

v_gmv_current_adjustments

只返回 active version 的扣減明細，供完整報表及稽核 export 使用。
