# 驗收基線

更新日期：2026-07-02  
目的：提供後續 Codex 每次修改 `nbs_analytics` 後的最低驗收標準，避免「只看頁面能開」就宣稱完成。

---

## 1. 核心原則

任何會影響資料、報表、API、upload、rollback、baseline 或模組邊界的改動，都必須做到：

```text
有測試
有 baseline 驗證
有服務健康檢查
有明確說明哪些未驗證
```

不得只憑：

- Streamlit 頁面有打開
- Vue 頁面有渲染
- API health 是 ok
- 單一截圖看起來正常

就宣稱整體完成。

## 5. Upload / Drift / Rollback 驗收

若涉及上傳或資料庫寫入，必須確認：

1. upload preflight 有 `batchSummary`。
2. `batchSummary` 顯示最早/最晚收款時間、金額合計、指定日期覆蓋狀態。
3. freshness update 不被誤判為 core drift。
4. core drift 會拒絕批次。
5. drifted DB 被 quarantine。
6. 正式 SQLite 回滾到 accepted state。
7. rollback 後 baseline matched。
8. stability history 有記錄。

不能只看「上傳成功」或「頁面沒有白屏」。

---

## 6. Vue / API 驗收

Vue 保持展示層角色。驗收重點：

- Vue 不自行計算正式收入口徑。
- Vue 使用 `/api/dashboard/summary` 的 `revenueTotals`。
- Vue ranking 使用 API 回傳的 `branchRanking` / `specialistRanking`。
- Vue upload/report 入口必須展示 backend gate result，不可吞掉 drift 或 rollback error。
- Navigation/hash 切換不得觸發 dashboard recompute。

API response contract 至少要保留：

```text
revenueTotals
dataFreshness
branchRanking
specialistRanking
scope / revenueScope
```

---

## 7. Streamlit 模組化驗收

若改動 Streamlit 模組：

- `app.py` 必須保持 thin entrypoint。
- 不要把 page rendering 大量搬回 `app.py`。
- `app_pages.py` 對 `app_workflows.py` 應保持明確 imports。
- 若繼續拆分，優先收斂 `streamlit_rendering` 星號匯入。
- 修改 rendering 不應改變 revenue scope、SQLite、AI cache 或 export schema。

建議跑：

```bash
.venv/bin/python -m pytest tests/test_app_module_boundaries.py -q
```

## 9. 完成回報格式

後續 Codex 完成任務時，建議用以下格式：

```text
已修改：
- ...

未修改：
- SQLite schema / 正式口徑 / baseline / export schema ...

驗證：
- py_compile: pass
- pytest target: pass
- baseline 2026-05: HKD 12,057,968 matched
- system_manager acceptance: passed

未驗證：
- ...
```

如果沒有跑測試，必須明確說「未驗證」，不能用推測語氣代替。
