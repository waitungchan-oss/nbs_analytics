# Beta 市場電商及同業銷售員範圍設計

日期：2026-10-13
狀態：待使用者審閱
範圍：`Beta comparison export` 的六張「市場電商及同業」工作表

## 目標

Beta 比較匯出中的「市場電商及同業」資料，改為只依銷售員名單納入與分類。銷售點名稱與單號前綴不再作為 Beta 的納入條件。正式 Dashboard、Forecast、SQLite、正式匯出，以及分社／門市歸屬規則維持不變。

名單外、空白、無法唯一識別或未匹配的銷售員不納入這六張 Beta 工作表，不得預設歸入客戶服務部。若來源提供穩定員工代碼，優先以代碼識別；無代碼項目只接受明確的正規化名稱別名，不以 fuzzy match 推測身份。`ctsit 杨慧如` 與 `004014 杨慧如` 必須保持為兩個不同的銷售員身份。

## 應用範圍與資料流

變更只套用至以下工作表：

- `市場電商及同業_經營統計`
- `市場電商及同業_旅行團統計`
- `市場電商及同業_票務總計`
- `市場電商及同業_每天旅行團交易人數`
- `市場電商及同業_每天票務交易數量`
- `市場電商及同業_線路種類每天統計`

主表的銷售員身份是 Beta 納入／分類依據；副表仍可透過既有單據關聯補充產品、線路或數量資料。單號可繼續用於主副表匹配，但單號前綴不能決定一筆資料是否屬於 Beta 名單。銷售點欄位可以作為明細維度保留，但不參與這六張表的納入或種類判斷。

使用者之後會上傳包含所有銷售員資料的主表及副表。只有當來源資料覆蓋 Beta 匯出所需日期範圍，且上傳、匹配與重建檢查成功，該範圍才能視為完整；若只上傳新月份，未覆蓋的歷史月份仍須標示可能不完整。不可把「含所有銷售員」等同於「已涵蓋所有歷史日期」。

## 舊快取與完整性提示

- 現存舊 Beta 匯出保留下載，不因本設計刪除或覆寫。
- 在完整來源重傳及 Beta 重建成功前，Beta 匯出區明確提示舊結果可能因過去的銷售點／單號前綴限制而缺漏；不得標示為完整的新口徑結果。
- 失敗或部分期間的上傳／重建不得解除提示。重建成功後只對已驗證覆蓋的日期範圍解除提示；其他未覆蓋期間仍保留提示。
- Beta 快取版本／指紋須包含新銷售員名單與分類規則，避免把舊邏輯產物當成新邏輯結果。正式匯出快取與其版本身份不變。

## 金額口徑與明確非目標

Beta 仍沿用正式口徑：不含收款類型「掛賬核銷」及收款方式「TT 退款轉團款」。訂單號仍可作主副表 join key；不得用它作名單篩選。

本次不改：

- 正式 Dashboard、KPI、Forecast、Backtest、SQLite 寫入或正式 workbook。
- 分社／門市規則、`BRANCH_NAME_ALIASES`、銷售點歸屬、分社彙總邏輯。
- 六張以外的 Beta 工作表或其他匯出 workbook schema。
- 主副表原有匹配鍵、金額歸屬和產品計算公式。

如需防止資料源重疊造成重複列，必須使用收款明細的穩定列身份；不得僅按訂單號去重，因同一訂單可有多筆收款。此去重只處理同一收款列在來源之間的重複，不合併不同收款事件。

## 驗收標準

1. 六張指定工作表均使用同一份十人 allowlist，沒有第十一位銷售員，也沒有十人名單中的缺漏。
2. 六人種類為「客戶服務部」，四人種類為「商務同業組」；未知或歧義身份不會被自動塞入任何一類，且有可稽核的排除／未匹配計數。
3. 改變銷售點名稱或單號前綴但維持同一銷售員身份，不改變 Beta 納入資格；名單外銷售員即使來自原四個銷售點或符合舊前綴也不納入。
4. 經營金額、旅行團／票務金額與每日統計，按各 sheet 語意與同一來源範圍核對；匹配的主表正式口徑金額不因副表缺列而消失或重複。
5. 對涵蓋日期範圍外的歷史資料，仍顯示不完整提示；只有完整來源重建及驗收成功的日期範圍可解除提示。
6. 分社規則相關檔案與正式結果不變；驗收包含 official surface regression checks。
7. 通過 findings-first Review、完整 pytest、Hermes 及適用的 UI/export acceptance；各證據需綁定同一 source fingerprint。

## 風險與處理

- 銷售員名稱寫法漂移可能造成誤排除：以穩定代碼優先；無代碼身份使用明確別名，未知／歧義列出可觀察計數，不做模糊自動匹配。
- 主副表日期範圍不一致可能令歷史不完整：以實際上傳涵蓋期和匹配結果判斷完整性，不只依檔案存在或最晚日期判斷。
- 舊 cache 可能已被使用者下載：保留下載但明示可能不完整；新舊快取身份分離，完整來源重建後才產生新口徑 cache。
- Beta 範圍放寬可能意外改變正式分社邏輯：所有新選取條件須限於 Beta 工作流程；分社邏輯需有不變性測試。
