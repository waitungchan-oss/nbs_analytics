# Frozen Baseline Revenue Scope Design

## 背景

Phase 2 baseline 已鎖定 `2026-05 分社 + 專職銷售組總營收 = HKD 12,057,968`，正式口徑為 `不含掛賬核銷與TT退款轉團款`。0625 批次中，`來源單據號 225JIA6515114503` 新增了 6 月 `掛賬核銷` 收款行，現有規則按來源單據號整單排除，導致 5 月已驗收旅費 `HKD 15,000` 被回溯排除，觸發 Drift 與 rollback。

## 目標

保留已驗收月份的歷史收入，不讓後續新上傳的排除類收款行回溯改動同來源單據號下的既有訂單。新上傳或既有資料中，`收款類型 = 掛賬核銷` 或 `收款方式 = TT 退款轉團款` 的收款行本身仍不計入正式營收。

## 規則

- 既有資料庫中的歷史收款單號不重寫、不改口徑。
- 上傳批次若包含已存在於 SQLite 的排除類收款單號，保留該行，避免全量快照漏寫歷史排除行而打開舊口徑。
- 上傳批次若包含 SQLite 尚不存在的新排除類收款單號，該行不寫入正式 SQLite。
- 新排除類收款單號不再因同一 `來源單據號` 回溯拖動其他非排除收款行。
- Phase 2 baseline gate 仍維持阻斷：若 `2026-05` 金額或正式口徑漂移，仍拒絕批次並 rollback。
- 此變更只調整寫入前的上傳批次保護，不直接重寫 SQLite 歷史資料。

## 驗收

- 針對同來源單據號 `歷史旅費 + 後續掛賬核銷` 的單元測試：旅費保留，新掛賬核銷不寫入。
- 針對 `0101-0625` 全量快照的單元測試：已存在的歷史掛賬核銷行保留，新掛賬核銷行跳過。
- 用隔離 DB `nbs_marketing_data.db.quarantine_20260626_100033_575908` 驗證 0625 批次若按新規則計算，`JIA 江嘉韵` 的 5 月 `HKD 15,000` 不被回溯排除。
- 全量測試通過。
- 系統 acceptance 通過。
